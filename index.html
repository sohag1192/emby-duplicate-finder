        🌐 Emby CORS & Connection Guide

        Why do connection or CORS errors happen?

        Web browsers enforce the Same-Origin Policy (SOP) and Cross-Origin Resource Sharing (CORS) rules that restrict web pages from directly requesting data from other domains or ports without proper headers.

        Common Causes & Solutions:

        1. Mixed Content (HTTPS vs HTTP):

          If you opened this web app via https://... (like GitHub Pages), but your Emby server is http://...:8096, the browser blocks the request.
          Solution: Check the "Enable CORS Proxy" option in the Connection Settings, or host Emby with an SSL/TLS domain (HTTPS), or run this HTML file locally on your computer via file:/// or local HTTP.

        2. Missing CORS Headers on Emby:

          If Emby is accessed through a Reverse Proxy (such as Nginx, Caddy, or Cloudflare), the proxy must allow Cross-Origin headers.

          Example Nginx configuration:

          location / {
    proxy_pass http://127.0.0.1:8096;
    proxy_set_header Host $host;

    # CORS Headers
    add_header 'Access-Control-Allow-Origin' '*' always;
    add_header 'Access-Control-Allow-Methods' 'GET, POST, DELETE, OPTIONS' always;
    add_header 'Access-Control-Allow-Headers' 'Content-Type, Authorization, X-Emby-Token' always;
    if ($request_method = 'OPTIONS') {
        return 204;
    }
}
        3. Using the Built-in CORS Proxy:

          Simply check the "Enable CORS Proxy" box under Connection & CORS Settings. This routes the API requests through a secure proxy server that adds the necessary CORS headers automatically.

        4. Allow Media Deletion in Emby:

          To delete duplicate files directly using this tool, make sure your Emby user/API key has permissions enabled under: Emby Server Dashboard -> Users -> [Your User] -> Allow media deletion from clients.
